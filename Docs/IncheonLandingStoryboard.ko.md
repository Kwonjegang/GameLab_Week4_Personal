# 인천 상륙 작전 — 카메라 연습용 스토리보드 v0.1

작성: 2026-09-25 / 상태: 기획 초안, 씬 구현 전

## 기준

사용자가 제시한 1~7번을 이번 범위로 삼는다. 별도 사용자 조작 없이 진행하며, 동료들이 피격된 뒤 주인공이 앞으로 달려가는 지점에서 끝난다. 처음 구상했던 포탄·동료의 희생·더 긴 회상은 이번 범위에 임의로 추가하지 않는다.

기존·무료 에셋을 우선하고 임시 외형을 허용한다는 사용자의 답변을 반영한다. 아래 시간·인원·각도는 비교를 시작하기 위한 제안이며 확정된 연출이 아니다.

사용자가 직접 연습할 중심은 카메라 위치, 구도, 회전, 이동, FOV, 전환, 흔들림, 후처리 강도와 타이밍이다. 보조 구현의 역할은 같은 사건을 반복해서 볼 수 있는 배우·배·효과의 재생 기반을 준비하는 것이다.

## 일곱 장면의 흐름

| 원안 | 사건 | 카메라 연습 | 필요한 기반 |
| --- | --- | --- | --- |
| 1 | 쓰러진 주인공이 하늘을 보며 두 번 깜박인다. 동료가 접근한다. | 낮은 POV, 위를 보는 각도, 더치 앵글, 작은 Tilt | 동료 접근, 눈꺼풀, 부상 색감 |
| 2 | 동료가 앉아 손을 뻗고 어깨를 흔들어 깨운다. | Tilt 정지, 얼굴과 손의 프레이밍 | 몸 낮추기, 손 뻗기, 어깨 접촉 |
| 3 | 위에서 피가 흐르고 붉은 기운이 짙어진다. 눈이 감긴다. | 주관적 화면 효과, 암전 타이밍 | 핏방울, 붉은 색감, 최종 검은 가림 |
| 4 | 흰 글씨 '40분 전.' 뒤에 바다·해변·산이 펼쳐진다. | 측면 ELS로 장소와 진행 방향 제시 | 한글 폰트, 해안 지형, 수면, 하늘 |
| 5 | 배 접근 → POV 진입 → 배 정지 → 동료 입수 → 주인공 입수 → 수중 이동 → 상륙 → 둘러보기와 끄덕임 | 공간 이동, POV 연결, 수면 통과, 시선 교환 | 배, 경로, 입수/수영/끄덕임, 수중 효과 |
| 6 | 앞선 인물이 물가에서 해변으로 걸어간다. 시야가 그를 따라간다. | POV 안에서 Pan/Tilt와 리드룸 | 동료의 보행 |
| 7 | 불빛 → 동료들의 피격 → 움츠림 → 전방 질주 | 시선 유도, 사건과 반응의 대비 | 점등, 피격/넘어짐, 자동 전진 |

## 해석과 미정 사항

- 1번의 30°는 시선이 지면에서 위로 들린 각도로 해석한다. 화면을 옆으로 기울이는 Dutch는 별도다. 위를 보는 각도 약 30°, 화면 기울기 약 10~15°부터 비교할 수 있다. Unity Transform에 특정 부호의 값을 그대로 넣으라는 뜻은 아니다.
- 최초 카메라 높이는 약 0.3~0.5m를 비교 시작점으로 제안한다. 비스듬한 하늘과 다가오는 동료가 같이 들어오는지 실제 화면으로 맞춘다.
- 2번의 손은 렌즈가 아니라 주인공의 어깨를 향한다. 화면 아래에 어깨 접촉 기준점을 두는 안이다. 사용자 요청대로 Tilt는 멈춘다.
- 5번을 아래에서 나눈 것은 반복 연습 단위다. 각 구간에 컷을 추가한다는 뜻은 아니며, ELS에서 POV로 이어진 뒤 연속된 시점을 유지할 수 있다.
- 5번 말미는 물가에 도착해 주변을 살피는 구간, 6번은 앞사람이 마른 해변 쪽으로 먼저 나아가는 구간으로 정리한다.
- 7번의 불빛 종류는 미정이다. 탐조등이나 총구 섬광으로 확정한 사실로 기록하지 않는다. 기본 요구는 점등/발광 직후 피격이 일어나는 것이다.
- 부상한 현재가 40분 전 이야기와 어떻게 연결되는지는 이후 확장분이다. 이번 끝에 새 부상 장면을 추가하지 않는다.

## 최소 배우와 공간 제안

- 주인공 P + 동료 A/B/C/D. 모델 1종을 복제하는 안이다. POV에 몸이 보이지 않으면 별도 1인칭 팔 모델은 필수가 아니다.
- A는 처음 깨우는 인물과 상륙 후 눈을 맞추는 인물로 재사용하는 안이다. 옷 색 등 작은 표식으로 구분한다. 7번에서 A도 반드시 쓰러져야 한다는 설정은 추가하지 않는다.
- B는 앞서 입수하고 첫 피격을 보여주는 인물, C/D는 옆에서 피격되는 동료들이다. 같은 애니메이션도 시작 시점을 달리한다.
- 배 1척, 해안 지형 1구역, 수면 1면, 산 실루엣, 하늘, 사건을 알릴 광원.
- 해변과 산은 같은 단순 지형으로 구성 가능하다. 실제 인천 지형을 고증하거나 복원한 기획은 아니다.

## 화면 효과의 역할

Volume Weight는 이미지 레이어의 알파나 화면 앞뒤 순서가 아니다. 여러 Volume은 설정을 섞는다. '검은 Volume을 피 위에 놓는다'는 의도는 아래 역할로 구현할 수 있다. 이는 설치된 Render Pipeline Core의 Volume.cs에 있는 priority/weight 정의를 참고한 설명이다.

| 결과 | 필요한 역할 | 실습할 값 |
| --- | --- | --- |
| 부상 색감 | Volume의 색·비네트·노출 | 강도, 전환 시간 |
| 위에서 흐르는 피 | 별도 화면 효과. 기존 Rain On Lens 수정 또는 혈흔 이미지 활용 후보 | 양, 속도, 붉은 색, 불투명도 |
| 눈 감기 | 최종 화면을 가리는 눈꺼풀 마스크 | 열림 정도, 개폐 속도 |
| 수중 시야 | 기존 Underwater 샘플과 Volume 연결 | 색·탁도·왜곡, 전환 시점 |
| 시간 자막 | 마지막에 그리는 텍스트 | 표시·퇴장 시점 |

목표 합성 순서: **장면 → 색감/수중 처리 → 피 효과 → 검은 눈꺼풀 → 회상 자막**. 이는 원하는 결과의 순서이며 아직 설정된 렌더링 순서가 아니다. 마지막 가림을 UI로 하거나 같은 전용 화면 효과 안에 넣을 수 있다. 기본 Vignette만으로 눈꺼풀 형태가 자동 생성되지는 않는다.

Unity의 [후처리 샘플](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.0/manual/Shader-Graph-Sample-Production-Ready-Post.html)은 흐르는 렌즈 물방울과 수중 표현의 기반을 제공한다. 피로 보이게 만드는 수정과 눈꺼풀은 별도 연결 항목이다.

수면과 수중 화면 효과는 다른 준비물이다. 아래에서 본 수면, 물 밖으로 나오는 순간의 전환, 배 내부로 수면이 보이는 문제는 샘플 적용 후 확인한다.

## 연습 환경의 역할 분담

| 보조 작업으로 준비할 것 | 사용자가 공부할 것 |
| --- | --- |
| 시작 위치 복원, 구간 재생, 배·배우 이동과 동작 | 숏 크기, 위치, 구도, FOV |
| 입수·점등·피격의 기준 시점 | 카메라 반응을 사건보다 앞/동시/뒤에 둘 때의 차이 |
| 효과 연결과 조절값 노출 | Volume 강도, 깜박임·암전·피·수중 효과의 타이밍 |
| 같은 사건의 반복 재생 | 한 변수씩 바꾸며 전후 비교 |

첫 실습은 1~3번을 제안한다. 기존 캐릭터를 활용하면서 더치 앵글·Tilt·가까운 구도·후처리를 한 자리에서 비교할 수 있다. 이후 4~5번의 공간 이동과 수면 통과, 6~7번의 사건 반응을 다룬다.

에셋별 근거와 후보는 Docs/IncheonLandingAssetPlan.ko.md에 정리했다. 이번에는 문서만 작성했으며 다운로드, 임포트, 패키지 설치, 새 모델/효과 제작, 씬 수정은 진행하지 않았다.

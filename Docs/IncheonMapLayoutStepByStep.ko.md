# 인천 상륙 작전 — 맵·배치부터 시작하는 실습 순서

작성: 2026-09-25. 사용자가 직접 수행할 안내이며 씬에 이 배치를 구현한 기록이 아니다.

## 진행 원칙과 역할

이번 순서는 **맵의 큰 형태 → 사건 위치 → 배·배우 배치 → 임시 화면 확인 → 공간 보정 → 움직임 연결 → 카메라 연출 → 배경·효과 마무리**다. 먼저 공간과 동선을 잡고, 장식에 시간을 쓰기 전에 화면으로 확인한다. 카메라를 확인한 결과에 따라 맵도 다시 조절한다.

사용자는 장소의 형태, 사건의 위치, 인물 간 거리와 방향, 사용할 동작, 카메라 구도와 타이밍을 결정한다. 에이전트는 경로 이동, 동작 연결, 구간 재생·초기화, 효과 연결 등 구현을 보조한다. 자동 연출을 완성해서 사용자 실습을 대체하지 않는다.

## 현재 연결 상태 갱신

이전 확인 이후 저장된 `Assets/Scenes/Incheon_Practice.unity`가 갱신되었다.

- Main Camera에 활성 CinemachineBrain이 있다.
- 활성 CinemachineCamera `CM_Opening`이 있다.
- Global Volume이 `IncheonSceneProfile` GUID를 참조한다.
- 저장된 씬에서 기존 FollowCamera 스크립트 참조는 발견되지 않는다.
- Movement는 여전히 활성이다. 고정 배치를 Play 모드에서도 유지하려면 해당 컴포넌트를 비활성화한다. GameObject 또는 Animator 전체를 끄라는 뜻은 아니다.

따라서 예전 안내의 ‘씬 저장과 Cinemachine/Profile 연결 미확인’은 최신 상태로 대체한다. 이 확인은 디스크의 연결 정보 기준이며 Game 뷰 재생 검증은 아니다.

## 1. 배치할 작업 공간을 만든다

1. Play 모드를 종료하고 Incheon_Practice 씬을 연다.
2. Hierarchy에서 Create Empty로 `Environment`, `Actors`, `Markers`를 만든다. 처음에는 Position/Rotation을 0, Scale을 1로 두어 부모의 크기·회전이 배치에 섞이지 않게 한다.
3. 환경 오브젝트는 Environment, 인물은 Actors, 사건 위치 표시는 Markers 아래에 정리한다. 기존 모델의 뼈대 안쪽 대신 캐릭터 전체 루트를 옮긴다.
4. 기존 캐릭터 한 명은 크기 비교 기준으로 남긴다. 모델의 Scale을 임의로 바꾸기 전에 배·바닥과 비교한다.
5. 이번 연습에서는 바다에서 육지로 향하는 방향을 월드 +Z로 정한다. 예시이므로 다른 축으로 통일해도 된다.

완료 기준: 어디가 바다 쪽이고 어디가 육지 쪽인지 Scene 뷰에서 설명할 수 있다.

## 2. 기본 도형으로 공간의 큰 형태를 만든다

GameObject → 3D Object에서 Plane, Cube, Sphere 등을 만들고 Inspector의 Transform으로 크기와 위치를 조절한다. 이런 임시 도형 배치를 블록아웃이라고 부른다. 기본 도형은 프로토타입과 크기 비교에 사용할 수 있다. [Unity 6 기본 도형 설명](https://docs.unity3d.com/6000.0/Documentation/Manual/PrimitiveObjects.html)

| 구역 | 먼저 만들 형태 | 확인할 것 |
| --- | --- | --- |
| 바다 수면 | 넓고 평평한 Plane, 임시 파란색 | 배가 이동할 거리와 ELS에서의 바다 면적 |
| 수중 바닥 | 수면보다 낮은 바닥 | 캐릭터 몸과 시점이 잠겨 이동할 공간 |
| 해안 경사 | 기울인 Cube 등으로 표시한 완만한 연결부 | 수중에서 해변으로 나오는 방향과 높이 관계 |
| 마른 해변 | 넓은 바닥 | 상륙·눈맞춤·피격·질주가 일어날 여유 |
| 산/언덕 | 큰 도형 몇 개의 실루엣 | 측면 ELS에서 해변 뒤의 공간을 읽을 수 있는지 |

수면 높이를 Y=0으로 두고 시작하면 비교하기 쉽다. 잠기는 구간은 수면 아래, 마른 해변은 수면 위에 둔다. 수중 바닥은 캐릭터 키보다 깊은 곳에서 시작해 해변으로 갈수록 높아지는 구상으로 잡는다. 정확한 이동 경로·지면 접지는 후속 보조 구현에서 연결한다.

임시 수면 Plane의 Collider는 꺼 둔다. 수면을 단단한 바닥으로 취급하면 입수 이동을 막을 수 있다. 육지와 바닥의 Collider와 구분한다. 불투명한 임시 수면은 아래쪽 공간 확인을 방해하므로 수중 배치 때는 임시로 수면을 숨겨 확인한다. 이것을 완성된 수중 표현으로 간주하지 않는다.

기존 연습용 Plane이 새 해변이나 수중 구간을 관통하면 실습 씬에서 비활성화하거나 위치를 조정한다.

완료 기준: 물 위·물속·육지의 높이 관계와 배에서 해변까지의 길이 설명된다. 현재 단계의 재질은 단색이어도 된다.

## 3. 사건이 일어나는 위치를 표시한다

작은 색깔 Cube 또는 Empty로 다음 지점을 표시하고 이름을 붙인다. 작은 Cube를 쓴다면 캐릭터와 충돌하지 않도록 표시용 Cube의 Collider를 끈다. Markers 안에는 배우를 넣지 않아 나중에 표시만 숨길 수 있게 한다.

| 이름 | 뜻 |
| --- | --- |
| Boat_Start | 배가 접근하기 시작하는 위치 |
| Boat_Stop | 배가 멈추고 입수를 시작하는 위치 |
| Water_Entry | 앞선 동료와 주인공이 입수할 공간 |
| Shore_Exit | 수면에서 올라와 해변으로 향하는 위치 |
| Nod_Point | 동료와 눈을 맞추고 끄덕이는 위치 |
| First_Hit | 앞선 동료가 피격되어 쓰러지는 위치 |
| Run_End | 주인공의 전방 질주가 끝나는 위치 |
| Opening_Wake | 도입부에서 쓰러진 주인공을 깨우는 위치 |

Boat_Stop → Water_Entry → Shore_Exit → Nod_Point → First_Hit → Run_End 순서로 손가락으로 따라가 보듯 동선을 확인한다. Boat_Start와 Boat_Stop은 서로 다른 위치다. Opening_Wake는 현재 시점의 별도 장면이며 회상 이동 경로 한가운데에 의무적으로 넣지 않는다. 기존 해변의 빈 공간을 재사용할 수 있다.

완료 기준: 스토리보드의 사건마다 어디에서 일어나는지 가리킬 수 있다. 좌표는 이후 구도와 재생 길이에 맞춰 바꿀 수 있다.

## 4. 배와 배우를 배치한다

1. 배는 내려받은 `kenney_watercraft-pack/Previews`에서 갑판과 입수 방향을 확인하고 하나를 고른다. 바로 고르기 어렵다면 배 자리와 크기를 Cube로 먼저 표시한다.
2. 선택한 배를 가져올 때는 `Models/FBX format`의 해당 FBX와 `Textures/colormap.png`, 배포 License.txt를 프로젝트 안의 전용 폴더에 복사해 둔다. Unity가 가져온 뒤 모델을 씬에 배치한다. 재질 연결이 자동으로 끝났다고 가정하지 않는다.
3. 캐릭터를 갑판 옆에 두고 문·난간·몸의 상대 크기를 비교한다. 배 크기를 조절해 여러 명이 서고 옆으로 입수할 자리를 확보한다. 머리가 구조물에 가리거나 입수 경로가 난간을 관통하는지 확인한다.
4. 기존 캐릭터 전체 루트를 복제해 주인공 P와 동료 A/B/C/D로 구분한다. 역할은 제안이며 화면을 확인하며 인원·간격을 바꿀 수 있다.
5. A는 깨우기/눈맞춤, B는 먼저 입수하고 앞에서 피격, C/D는 옆에서 피격되는 역할로 배치한다. 주인공의 전진 방향과 인물의 얼굴 방향을 함께 확인한다.
6. 우선 정지 배치만 한다. 움직임 연결 후에는 같은 배우가 구간마다 이동한다. 배·해변·깨우기 장소를 검토할 때마다 필요한 지점으로 옮겨 봐도 된다.

현재 Animator의 기본 Idle은 삭제 보정 때문에 Crouch_Idle이다. 서 있는 대기를 원하면 다음 동작 연결 단계에서 내려받은 UAL1의 Idle_Loop을 확인한다. 모델 Scale을 바꿔 웅크림 자세를 보상하지 않는다.

완료 기준: 배 위에서 누구를 바라보는지, 해변에서 누구와 눈맞춤하는지, 누가 먼저 쓰러지는지 정지 배치만으로 설명할 수 있다.

## 5. 기본 조명과 세 위치의 화면을 확인한다

기존 Directional Light로 인물과 지형을 읽을 수 있을 정도의 밝기를 확보한다. 원하는 야간 분위기가 있더라도 먼저 상대 위치를 알아볼 수 있는 상태에서 배치를 검사한다.

기존 CM_Opening의 정교한 이동이나 전환을 만들기 전에 Scene 뷰를 아래 세 위치에서 살펴본다. Scene 뷰 확인 후 필요하면 기존 카메라로 실제 Game 화면을 비교한다. Scene 뷰와 Game 뷰는 화각·화면 비율이 다를 수 있다.

| 임시 확인 위치 | 볼 대상 | 배치에서 고칠 것 |
| --- | --- | --- |
| 해안 측면 멀리 | 바다·배·해변·산 | 산이 해변을 가리는지, 배가 너무 작은지, 수면 가장자리가 드러나는지 |
| 배 위 주인공 눈높이 | 앞선 동료·입수할 방향·해안 | 난간/다른 인물이 시선을 막는지 |
| 해변의 낮은 주인공 눈높이 | 다가와 몸을 낮추는 동료·하늘 | 얼굴과 손을 담을 공간, 배경 실루엣의 겹침 |

여기서는 장면이 성립하는지 검사한다. 문제가 보이면 배우 간격이나 산·배의 위치를 조절한다. 본격적인 Dutch, Damping, 이동 경로, 컷 타이밍은 다음 실습에서 비교한다.

완료 기준: 중요한 세 화면을 담을 공간이 있다. 첫 맵 배치 작업은 여기까지를 목표로 한다.

## 6. 동작 선택과 반복 재생 기반을 연결한다

사용자는 남긴 기존 동작과 다운로드 UAL1의 Swim_Fwd_Loop, Swim_Idle_Loop, Walk_Loop, Idle_Loop을 실제 모델에서 보고 적합 여부를 정한다. 에이전트는 리타기팅 설정 확인, 동작 전환, 경로 이동, 구간별 시작 위치 복원과 재생을 보조한다.

먼저 한 구간이 재현되는지 확인한 후 다음 구간을 연결한다. 깨우기 장면의 손 접촉, 입수와 수면 통과, 피격 후 자세 유지처럼 보정이 필요한 항목을 분리해 다룬다.

완료 기준: 같은 구간을 재시작했을 때 배우가 같은 위치와 순서로 움직인다.

## 7. 카메라 연출과 후처리를 실습한다

공간의 첫 점검은 측면 ELS → 배 위 POV → 낮은 도입부 POV로 해도 된다. 움직임이 준비된 뒤 본격적인 연출 실습은 기존 계획대로 도입부 1~3번부터 시작하고, 4~5번, 6~7번으로 넓힌다.

사용자가 조절할 중심은 카메라 위치·높이·각도·Lens·Dutch·반응 속도·움직임·전환 및 Volume 강도·효과 타이밍이다. 임시 지형에서도 화면 전후 비교를 할 수 있다.

## 8. 화면을 보며 배경과 효과를 마무리한다

확정한 화면에 필요한 범위부터 모래·해안 재질, 바위·산 형태, 수면 재질, 물보라·연기 등을 추가한다. 다운로드한 sand_02/coast_land_rocks_01의 텍스처는 표면 재료이며 완성된 해변 맵이 아니다.

프로젝트에 이미 임포트한 WaterLake는 수면 표현 후보다. 수중 색감·왜곡과 물 밖으로 나오는 전환은 별도 확인이 필요하다. 샘플은 물 재질 학습의 출발점으로 사용할 수 있다. [Shader Graph 17 Water 샘플](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.0/manual/Shader-Graph-Sample-Production-Ready-Water.html)

## 사용자에게서 받을 다음 결과

씬을 저장하고 배·상륙 지점·눈맞춤 위치·첫 피격 위치·깨우는 위치가 어디인지 공유하면 된다. 화면 구성이 어려운 지점도 함께 설명하면 해당 위치를 기준으로 보조 구현과 카메라 실습을 이어갈 수 있다. 새 외부 에셋 구매나 추가 제작은 현재 첫 배치의 전제 조건이 아니다.
